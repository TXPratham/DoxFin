# DoxFin Architectural Rules

These rules apply unconditionally to all agents, subagents, and automated code generators working on the DoxFin codebase.

## 1. Deterministic Calculation Mandate
- **Rule:** Never allow an LLM or probabilistic model to perform financial calculations or return computed mathematical figures directly.
- **Implementation:** All margins, growth rates, ratios, and differences must be computed by deterministic Python functions with explicit types and edge case handling (e.g. division by zero, negative denominator, negative equity).
- **Format:** Store formulas and calculated outputs in Pydantic models or typed dictionaries.

## 2. Evidence Grounding & Citation Mandate
- **Rule:** Any claim, summary, or anomaly explanation generated by an AI model must be accompanied by a verifiable citation.
- **Citation Structure:**
  - `document_name`: string (e.g. `"Reliance_FY25_Annual_Report.pdf"`)
  - `page_number`: integer (1-indexed)
  - `section_title`: string (e.g. `"Management Discussion & Analysis - Raw Material Costs"`)
  - `snippet`: exact text excerpt from the document
  - `table_id` / `chart_id`: optional identifier if extracted from a table/chart

## 3. Large Document Processing & Selective Triage
- **Rule:** Never ingest an entire 400–500 page PDF into a single LLM context window.
- **Triage Pipeline:**
  1. Classify page types (Text, Table, Chart, or Decorative/Skip).
  2. Filter out non-financial pages (cover art, generic photo pages, boilerplate disclaimers).
  3. Send financial tables to specialized table parsers (Docling/Camelot).
  4. Send complex visual charts to vision models.
  5. Chunk text with semantic headings and page metadata for vector indexing (FAISS).

## 4. Privacy & Multi-Tenant Isolation
- **Rule:** Financial documents are sensitive enterprise data.
- Never log raw customer financial data or PDF excerpts to unencrypted third-party logging platforms.
- Ensure tenant data isolation where tenant datasets, embeddings, and caches are partitioned.
